# CommonUI & Input Architecture

## 문제와 기존 구조

기존 UMG 상점은 Controller의 입력 모드 전환과 위젯의 구매·복제 이벤트를 함께 사용했다. 개인 후속 리팩터링에서는 상품 그리드와 원래 Blueprint 연출을 재사용하고 화면 활성화와 모달 포커스를 CommonUI로 연결했다.

## 화면 계층과 선택 이유

UShopLayer가 UCommonActivatableWidgetStack을 소유하고 UShopScreen이 WBP_MatchMap_ShopUI를 담는다. UShopConfirmation은 별도 Activatable 항목이고 화면은 WBP_ShopConfirmation이 가진다. 한 화면을 닫으면 하위 화면과 이전 버튼 포커스로 복귀한다. 복귀 대상은 bAutoRestoreFocus로 CommonUI가 저장한다. 게임 조작 중 상시 표시되는 HUD는 기존 UMG와 모델 구독으로 유지했다.

메뉴 활성화와 화면 수명은 CommonUI, 실제 구매 판정은 서버, 상품 클릭의 단순 전달은 기존 Blueprint가 담당한다. 이름의 접두사·접미사를 해석하던 버튼 분류는 명시적인 버튼 바인딩으로 바꿨다. Focusable 속성은 에디터에서 편집한다.

## UI 입력 액션

처음 리팩터링은 CommonUI를 스택·입력 모드·포커스 대상에만 쓰고 뒤로 가기·확인·LB/RB를 화면 코드의 키 판정으로 처리했다. 후속 개선에서 키 판정을 지우고 CommonUI 액션으로 옮겼다.

- DT_UIInputActions에 Confirm·Back·ShopClose·ShopPreviousCategory·ShopNextCategory 행을 둔다. BP_UIInputData가 Default Click·Back을 지정하고 프로젝트 설정(Common Input)이 이를 가리킨다.
- 상점 화면은 bIsBackHandler로 뒤로 가기를 받고, 상점 키와 LB/RB는 RegisterUIActionBinding으로 등록한다.
- 상품 확인은 포커스된 버튼의 기본 Accept 처리에 맡겨 패드와 마우스가 같은 클릭 경로를 지난다.
- 확인 모달의 버튼은 TriggeringInputAction에 Default Click·Back을 지정한다. CommonButton이 바인딩과 키 표시 위치(UCommonActionWidget)를 관리한다.
- 사용할 수 있는 패드·키보드 아이콘 에셋이 프로젝트와 엔진에 없어 키 이름 텍스트로 표시한다. 입력 방식이 바뀌면 Enter·Esc와 패드 버튼 이름이 바뀐다.

결정 근거와 계약은 [Architecture](https://github.com/chungheonLee0325/VALORANT/blob/main/Doc/UIRefactoring/Architecture.md)에 정리했다.

## 시작·유지·종료 입력

UAgentInputComponent는 상점 중 Move·Look·Fire·Skill·Weapon Switch의 새 동작을 차단한다. 메뉴 진입 시 ReleaseGameplayInput이 진행 중인 발사·점프·앉기·걷기·스파이크 입력을 정리한다. 종료 이벤트는 기존 상태를 해제할 수 있다. Controller는 게임 입력 복귀 시 눌린 키를 비운다.

이 선택은 UI 입력을 막는 것과 이미 시작된 게임플레이를 끝내는 것을 각각 처리하기 위한 것이다. 메뉴 안에서 키를 누르고 닫거나 발사 중 상점을 여는 경우를 따로 검사한다.
