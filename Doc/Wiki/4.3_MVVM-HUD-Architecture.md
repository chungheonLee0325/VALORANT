# MVVM & HUD Architecture

## 상태 수명 분리

기존 UMatchMapHUD에는 체력·아머·탄약, 스킬 행 검색과 스택, 매치 단계, 순간 연출과 구독 수명이 모여 있었다. 개인 개선에서는 지속 상태와 스킬 슬롯을 분리하고 기존 Blueprint의 연출 이벤트를 보존했다.

UCombatHUDViewModel은 AttributeSet·CreditComponent·현재 무기에서 스냅샷을 읽고 이벤트에 반응한다. UHUDAbilityBarModel은 현재 PlayerState와 요원 행을 묶어 슬롯 ID·아이콘·현재/최대 스택을 공급한다. 슬롯 수만큼 UObject를 만들지 않는다. UMatchMapHudTopWidget은 시간·점수·팀 카드를 계속 맡는다.

## 네이티브 FieldNotify

UShopViewModel은 UMVVMViewModelBase와 FieldNotify를 사용한다. 화면이 델리게이트를 구독해 표시를 갱신하는 네이티브 MVVM이다. UMG 에디터의 MVVM View Binding은 미적용이다.

게임플레이의 값은 서버와 복제 객체가 소유한다. ViewModel은 로컬 표시를 위한 스냅샷과 선택 상태를 갖는다. 화면을 닫으면 선택·피드백을 정리하고, 서버에 보낸 구매의 대기는 식별자로 추적한다.

## 이벤트와 표현 계약

Controller·Pawn·AttributeSet·CreditComponent가 바뀌면 이전 구독을 해제하고 현재 스냅샷을 읽는다. 현재 Pawn이 같아도 장착 Interactor가 바뀌면 탄약을 다시 읽는다. 화면 제거 시 타이머와 태그 델리게이트를 정리한다.

HUD 스킬의 레이블·패널 여덟 개는 필수 BindWidget으로 연결한다. 기존 에셋 내부 이름과 Blueprint 그래프를 유지하며 타입이 맞는지 컴파일한다. HUD를 다시 구성할 때 원래 키 텍스트와 아이콘을 복원해 문자열 누적을 막는다. 글꼴·그림자·배치와 충전 연출은 WBP에서 조정한다.

## 검증과 한계

스킬 구매·사용 1/1 → 0/1, 무기 전환·발사·재장전, HP·아머·점수, HUD 반복 생성과 카드 수를 확인한다. AttributeSet과 GameState는 서로 다른 패킷에 올 수 있어 두 상태를 각각 기다린다. 같은 표시 값은 알림을 생략하지만 CPU 개선율은 측정하지 않았다.
