# Multiplayer Regression Testing & AI-assisted Development

## 분석과 구현

팀 프로젝트의 기존 위젯과 호출 관계를 조사하고 서버 구매·UI 수명·Actor 정리의 경계를 개선한 개인 후속 작업이다. AI 코딩 에이전트는 코드 탐색·구현·빌드와 문서 작성을 보조했다. AgentMCP는 UE 5.5.4의 정확한 Valorant 작업트리에 연결해 실제 Widget Tree·그래프·바인딩을 읽고 WBP를 수정·컴파일하는 데 사용했다. 입력 후속 개선에서는 UI 입력 DataTable·Input Data·모달 WBP를 만들고 BindWidget 계약을 확인했다.

리뷰에서 부착 성공 전에 소유권이 바뀌는 월드 획득 경로를 다시 찾았다. 무기 초기화에서 원격 참조가 준비되기 전 역참조한 크래시도 실제 로그로 추적했다. 에이전트의 결과는 빌드, 코드 검토, 실패 주입과 원격 상태 관찰을 거쳐 반영했다.

## 재생과 결과 계약

Run-UIRegression.ps1은 localhost의 실제 MatchMap에서 호스트 1개와 원격 3개를 실행한다. 네 요원이 확정돼야 검사를 시작한다. 화면용 원격은 DX12이고 나머지는 NullRHI다.

각 검사는 UIRegressionChecks.json의 안정적인 ID와 실행 프로세스를 가진다. 모든 필수 ID가 정확히 한 번 PASS여야 성공한다. 누락은 NOT RUN, 조건 거부는 BLOCKED, 중복·실패·비정상 종료는 실패 종료로 처리한다. results.json은 커밋, 필수 개수, 결과와 발생 횟수를 담는다.

개발 빌드, 명시적 실행 플래그, 루프백 연결 조건을 모두 만족해야 시험 상태를 바꿀 수 있다. 스크립트가 생성한 프로세스는 실행 후 종료한다. 클래스 Spawn 거부를 이용한 실패 주입은 동기 범위에서 복구하고 Actor 스폰 콜백도 제거한다.

## 무엇을 비교했는가

- 서버 구매 판정·잔액·장비 슬롯과 Actor 수.
- 원격 복제된 재화·소유권·3인칭 메시와 실제 HUD.
- 모달 확인·취소와 UButton 포커스.
- CommonUI 라우터의 활성 액션 바인딩과 입력 방식별 키 표시.
- 상점 입력 차단과 연속 발사 종료, 눌린 키 해제.
- 타임아웃 직후 새 구매와 늦은 응답.
- 스킬 스택 감소, 피격·킬 피드, HUD 재생성.

HP가 먼저 복제된 프레임에 점수도 도착했을 것으로 가정한 검사가 실패한 적이 있다. 두 데이터 소스가 각각 도착할 때까지 기다린 뒤 UI 값으로 다시 확인했다. 이전 개발 버전의 검사 수를 공개 Release 결과로 복사하지 않고 새 빌드에서 재실행했다.
